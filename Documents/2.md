Yes, if you install it in a `venv`, you normally have to activate it. However, you can bypass this by using an **alias**. This allows you to run your custom Aider from anywhere without manually activating the virtual environment every time.

Here is how to set it up.

### Method 1: The "Lazy" Way (Direct Path)
You don't strictly *need* to activate the virtual environment to run the code inside it. You just need to point directly to the python executable or the `aider` script inside that `venv` folder.

If your project is at `~/custom-aider` and you created a venv named `venv`, the executable lives here:
*   **Mac/Linux:** `~/custom-aider/venv/bin/aider`
*   **Windows:** `C:\Users\You\custom-aider\venv\Scripts\aider.exe`

You can just run that path directly, and it will automatically use the libraries installed in that environment.

### Method 2: Creating a Permanent Alias
To make this easy (so you can just type `aider` or `my-aider`), add an alias to your shell configuration.

#### For Mac / Linux (Bash or Zsh)
1.  Open your shell config file (usually `~/.bashrc` or `~/.zshrc`) in a text editor.
2.  Add the following line at the bottom:
    ```bash
    alias my-aider="~/custom-aider/venv/bin/aider"
    ```
    *(Replace `~/custom-aider` with the actual path where you extracted the folder).*
3.  Save the file and run `source ~/.zshrc` (or `.bashrc`) to apply changes.
4.  Now, you can simply type `my-aider` in any terminal window.

#### For Windows (PowerShell)
1.  Open your PowerShell profile by running:
    ```powershell
    notepad $PROFILE
    ```
    *(If it asks to create the file, say yes).*
2.  Add this function to the file:
    ```powershell
    function my-aider {
        & "C:\path\to\custom-aider\venv\Scripts\aider.exe" $args
    }
    ```
3.  Save and restart PowerShell.
4.  Now you can type `my-aider` to run it.

### Summary
*   **Do I need to activate every time?** No, not if you use the full path to the executable.
*   **Can I run it with an alias?** Yes, pointing an alias to the `venv` executable is the best way to use your custom version system-wide.
